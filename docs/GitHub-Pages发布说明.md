# 发布到 GitHub Pages

本版访问密码为 `88888888`。密码入口、图片和脚本均使用相对路径，可发布在 GitHub Pages 的仓库子路径下，无需自己的服务器。

## 上传并发布

1. 登录 GitHub，新建一个公开仓库，例如 `kailong-menu`。
2. 解压“凯隆餐室-优化版.zip”，将优化版文件夹**里面的内容**上传到仓库根目录。根目录应直接看到 `index.html`、`css`、`js`、`images`，不要再包一层“凯隆餐室-优化版”文件夹。
3. 确保图片文件夹中的照片一并上传，图片路径和大小写不要改动。
4. 仓库页面打开 **Settings → Pages**，选择从分支发布（Deploy from a branch）。
5. 选择 `main` 分支及 `/ (root)` 目录，保存。
6. 等待 GitHub 发布完成，在 Pages 页面打开显示的网站地址。通常为 `https://你的用户名.github.io/kailong-menu/`。
7. 用电脑及手机打开网址，输入密码，检查选菜与预览，再将链接或二维码分享给需要访问的人。

如果账户、组织或仓库页面没有上述选项，请根据 GitHub 页面提示处理；部署方式和入口以账户实际可用功能为准。

## 访问方式

- 首次访问显示密码页。
- 输入正确密码后进入菜单。
- 不勾选“记住访问”，同一浏览器标签页刷新不必重输；关闭该标签页后再次进入需输入密码。
- 勾选“记住访问”，当前浏览器记住 30 天。
- 页面顶部“退出访问”会清除此浏览器的访问记录，重新显示密码页，选菜和资料不会删除。
- 浏览器禁用存储时仍可输入密码进入当前页面，刷新后可能需要再次输入。

## 修改密码

编辑 `js/access-config.js`：

```javascript
window.MENU_ACCESS = { password: '你的新密码', rememberDays: 30 };
```

修改后上传覆盖同名文件，等待重新发布。更改密码后，刷新页面时旧的访问记录会失效；已打开的网页仍需刷新才会载入新密码。忘记密码时，也可直接修改此文件重新发布。

## 更新菜单

直接更新仓库中的文件，会触发 Pages 重新发布。网页“菜品管理”中的修改仅保存在当前浏览器，不会自动更新仓库或所有访客的菜单。修改默认菜品需更新 `js/dishes.js`；自定义图片也应随项目上传。

这是轻量访问入口，适合避免普通访客随意浏览。公开仓库、网页源文件、菜品数据和图片仍可以被读取，不作为机密资料保护方式。菜单选择和资料修改仍由访客各自浏览器保存，没有联网同步。
