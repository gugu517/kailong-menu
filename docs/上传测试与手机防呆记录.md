# 上传测试与手机防呆记录

## 发现并修复的问题

修复前在线复现：先上传一张正确照片，再选择错误格式文件，预览仍显示新照片，但保存后重新编辑会退回原照片。

现在照片只有在成功解码、压缩及校验后才替换草稿。失败的选择保留上一张有效照片，显示中文原因；连续选图以最后一次选择为准，取消编辑后的旧处理任务不会影响另一道菜。

菜单和备份导入也会记录当前导入操作，避免较早的异步读取干扰后一次选择。损坏 JSON 使用中文提示。

## 手机体验与防呆

- 手机页减少装饰与介绍；套餐默认收起，可直接开始选菜。
- 六个分类完整显示；搜索与分类在浏览菜品时保持在页面顶部。
- 底部保留“已选”和“预览”两个主要操作。未选菜时预览不可用，提示先选择菜品。
- 已选菜单使用弹层，不必跳到长页面末尾；“继续选菜”回到原浏览位置。
- 换菜从已选弹层返回相应分类；数量保持一致。
- 清空菜单、替换套餐、导入覆盖及恢复默认仍有明确确认。
- 菜品管理、数据备份、餐厅设置与退出访问收进“更多”。
- 上传区域放到编辑窗口顶部，提供“选择照片”和“拍照”；保存按钮固定在窗口底部。
- 处理照片时禁用保存并显示进度；处理成功后提醒保存。
- 提供“撤销换图”，还原原照片，保留文字修改。
- 存在未保存修改时，关闭或按 Escape 会询问“返回编辑/放弃修改”。
- 输入文字使用适合手机的字号；操作按钮扩大触摸区域。
- 预览窗口的关闭和打印按钮保持可见，菜单内容独立滚动。

## 验证范围

- 浏览器 320×568、390×844 视口无横向溢出；选择、清空确认、换菜、更多操作和预览均已检查。
- “拍照”输入分支用 JPEG 文件模拟验证；没有使用真实手机摄像头或测试系统相机权限。
- 桌面侧栏正常恢复。73 道菜的简洁打印版仍为两页，菜名无遗漏。
- 11 项数据回归检查通过；检查期间没有脚本错误或警告。
- 照片与菜品编辑仅在当前浏览器生效。要更新所有访客的默认资料，需要修改 GitHub 中的菜品资料及图片。
